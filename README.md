# DubParty.

Игра для компании: озвучиваете сцены из видео, меняете голос эффектами, смотрите результат вместе и голосуете за лучший голос.
Работает в браузере, без своего сервера: паки и видео хранятся в IndexedDB, игроки соединяются напрямую по WebRTC.

## Запуск

```bash
npm install
npm run dev        # http://localhost:5173
npm run build      # dist/index.html — один самодостаточный файл, открывается двойным кликом
npm run typecheck
```

## Возможности

- **Паки сцен** готовит ведущий: создание в редакторе (видео, роли, реплики с таймкодами, фоновая дорожка) или импорт из ZIP, файлов или папки.
  Понимает паки The Choicer Voicer / Dub Together (`dub_video` + `.ini`/`.txt` реплик + `.ogg`), SRT/VTT, JSON и свой формат `pack.json`.
- **Только онлайн, каждый со своего устройства.** Ведущий создаёт комнату и делится ссылкой или кодом.
  Друзья заходят со своих телефонов, выбранная сцена (видео, реплики, фон) сама скачивается к ним.
- **Выбор ролей** нажатием на свободную роль, кнопки «Случайно» и «Перевыбрать».
- **Запись:** каждый записывает свою роль у себя и отправляет, записи расходятся всем.
- **Просмотр и голосование:** «Показать всем» запускает видео у всех сразу, каждый голосует за лучший
  голос со своего телефона, ведущий объявляет победителя.
- **Эффекты голоса:** бурундук, великан, демон, робот, рация, телефон, эхо, пещера, под водой.
  Эффекты не разрушают запись: их можно менять после, они звучат при просмотре и попадают в сохранённое видео.
  Можно слышать себя с эффектом в наушниках прямо во время записи.
- **Два языка интерфейса:** русский и английский, переключатель на главной.
- **Настройки звука** (шестерёнка в шапке): общая громкость, голоса, звук из видео, фон, оригинальные реплики;
  микрофон — устройство, громкость записи, шумо- и эхоподавление, автогромкость, самопрослушивание.
  Применяются сразу и запоминаются.
- Сравнение с оригинальными репликами, сохранение дубля видеофайлом (WebM).

## Устройство

```
src/
  lib/
    audio/
      engine.ts                 AudioContext, декодирование, VideoMixer — синхронизация дорожек с <video>
      effects.ts                описания эффектов и графы Web Audio для них
      pitch-shifter.worklet.js  AudioWorklet: сдвиг высоты голоса без изменения длительности
      mic.ts                    микрофон, индикатор уровня, мониторинг с эффектом
      exportVideo.ts            запись итогового видео (captureStream + микс Web Audio)
    pack/                       парсеры форматов, импорт и экспорт паков
    store.ts                    IndexedDB с запасным хранением в памяти
  i18n/                         словари ru/en и хук useT()
  net/                          онлайн-комнаты: WebRTC-канал с передачей файлов и логика ведущего
  state/                        навигация, настройки (zustand), логика игры и связка с комнатой
  components/                   лента реплик, модалки, выбор эффекта, индикатор микрофона
  views/                        экраны: главная, редактор, настройка, запись, просмотр
  styles/                       токены дизайна, база, компоненты, анимации
```

Весь звук идёт через один граф Web Audio. Записанные голоса, оригинальные реплики и фон — это `AudioBuffer`,
которые `VideoMixer` запускает по часам `AudioContext` с точностью до сэмпла и пересинхронизирует при перемотке,
буферизации или расхождении больше 60 мс. Каждая дорожка проходит через свою цепочку эффекта. Та же цепочка
используется для мониторинга микрофона и для экспорта видео, поэтому слышно везде одно и то же.

Сдвиг высоты (бурундук, великан, демон) сделан на двух скользящих отводах линии задержки с окнами sin²
(подход Chris Wilson «Jungle»). Задержка около 30 мс, и микшер её компенсирует, запуская такие дорожки раньше.

## Аккаунты (Supabase)

Регистрация по email и паролю с кодом подтверждения из письма, вход, сброс пароля кодом (`src/lib/auth/`, `src/views/Auth.tsx`).
Сервер аккаунтов — бесплатный проект [Supabase](https://supabase.com). Пока он не подключён, кнопка «Войти» скрыта.

Подключение:

1. Создайте проект на supabase.com.
2. **Authentication → Sign In / Providers → Email**: включены «Enable Email provider» и «Confirm email».
3. **Authentication → Emails → Templates**: в шаблонах **Confirm signup** и **Reset password** вставьте код
   `{{ .Token }}` (например: «Ваш код подтверждения: {{ .Token }}»), чтобы в письме был код, а не только ссылка.
4. **Authentication → Emails → SMTP Settings**: подключите свой почтовый сервис (Resend, Brevo, Mailgun…).
   Встроенная почта Supabase отправляет письма только адресам участников проекта и с жёстким лимитом,
   для настоящих пользователей нужен свой SMTP.
5. **Project Settings → API**: возьмите *Project URL* и ключ *anon public* и задайте их как переменные репозитория:
   ```bash
   gh variable set SUPABASE_URL --body "https://xxxx.supabase.co"
   gh variable set SUPABASE_ANON_KEY --body "eyJ..."
   ```
   Ключ *anon* предназначен для браузера и публичен. Ключ *service_role* никуда не вставляйте.
   Для локальной разработки те же значения кладутся в `.env.local` как `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY`.

## Сеть

Онлайн-режим работает без своего сервера: устройства соединяются напрямую по WebRTC (`src/net/`).
Для знакомства устройств используется бесплатный публичный сервер PeerJS (`0.peerjs.com`), через него
идут только служебные сообщения, а видео и записи передаются напрямую. Ведущий хранит состояние комнаты
и раздаёт его остальным.

- Чтобы ссылка-приглашение работала, сайт должен быть опубликован (Netlify, Vercel, GitHub Pages и т.п.).
  С `localhost` или из файла друзья смогут зайти только по коду, открыв у себя ту же версию.
- Примерно в 10–20% мобильных сетей прямое соединение невозможно без TURN-сервера. Если у кого-то
  не подключается, добавьте TURN в `PEER_OPTIONS.config.iceServers` в `src/net/room.ts`.
- Для серьёзной нагрузки лучше поднять свой PeerJS-сервер (`peerjs-server`) вместо публичного.

## Поддержка браузеров

Chrome и Edge поддерживают всё. Safari 17+ поддерживает запись и эффекты, а экспорт видео зависит от версии.
Видео OGV (Theora) Safari не воспроизводит — перегоните его в MP4 и замените в редакторе.
